# Local image build check

`build-local.sh SOURCE_ARCHIVE EXPECTED_SHA256 OUTPUT_DIR SOURCE_COMMIT` builds the five official production Dockerfiles for `linux/amd64` from a caller-curated, frozen repository archive. The archive must have the repository root at its root and exclude secrets and local dependencies. The script validates its SHA-256, extracts into a temporary directory, rejects common private files, uses the default same-origin frontend build settings and records logs, image IDs, sizes, architecture, and durations in an initially empty output directory. The 40-character lowercase `SOURCE_COMMIT` is passed to the frontend Dockerfiles for their fixed public-source link; the operator must establish that it is the public commit corresponding to the archive. It creates local tags only; it never pushes, starts services, or deploys. API, worker, beat worker, and migrator share the backend image and use different runtime entrypoints. Each build has a 3600-second default timeout; `PLANE_BUILD_TIMEOUT_SECONDS` can lower it.

The archive digest identifies the source snapshot; it does not make images bit-reproducible. Official Dockerfiles use mutable base tags, package repositories and network downloads. Docker's standard CA validation remains enabled. An operator must independently review the archive for sensitive contents; filename checks cannot prove it is secret-free.

Browser build defaults use an empty same-origin API URL, `/god-mode` for admin, `/spaces` for space, and `/live` for live. Space's server-side public issue metadata loader additionally needs runtime `PLANE_INTERNAL_API_ORIGIN` set to an explicitly trusted HTTP(S) origin such as `http://api:8000` on the private application network. It accepts only an origin, not a path, credentials, query, or fragment; redirects are refused. This server-only value is not derived from the request Host or forwarded headers and is never used as a browser URL. If omitted or invalid, public pages fall back to generic metadata. Verify internal networking, permissions, and actual metadata at deployment; image building alone does not validate the complete application.
